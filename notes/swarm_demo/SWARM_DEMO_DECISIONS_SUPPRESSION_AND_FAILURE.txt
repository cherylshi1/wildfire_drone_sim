SWARM_DEMO_DECISIONS_SUPPRESSION_AND_FAILURE
============================================

Date: 2026-05-25
Category: Fire model, suppression scoring, pass/fail policy

1) Suppression progress metric
- Formula:
  suppression_progress = 1 - (current_fire_area_sqm / peak_fire_area_sqm)
- Clamp to [0, 1].
- Reason: stable % progress relative to worst observed fire size.

2) 24-hour failure window mapping
- Sim time scale: 1 demo second = 15 operational minutes.
- Therefore 24 operational hours = 96 demo seconds.
- Failure trigger:
  - elapsed since ignition >= 24h window
  - suppression_progress < 0.98
- Reason: explicit demo KPI tied to incident response target.

3) Deterministic vs random behavior
- Deterministic:
  - suppression progression math
  - failure check condition
  - success threshold check (>= 98%)
- Stochastic:
  - suppression error event at first detection (5% chance)
  - error mode choice (delay or reignite)
  - probabilistic thermal detection roll
  - spread spawn randomness with wind bias

4) Failure alert behavior
- Failure alert now one-shot (no repeated re-trigger spam).
- Reason: cleaner demo output and less HUD noise.

5) Adaptive performance control layer
- Added optional adaptive mode (env switch) that changes incident rules based on live
  performance score (coverage, detection speed, suppression progress, burn impact).
- When enabled:
  - required suppression goal becomes dynamic (configurable min/max)
  - failure window becomes dynamic (configurable min/max hours)
  - suppression error probability becomes dynamic (configurable min/max)
  - detection probability scale and growth rate scale become dynamic
- Reason: make the scenario controllable and variable by performance instead of fully fixed.
